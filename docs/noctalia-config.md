# Noctalia configuration

`noctalia-config` synchronizes owned UI preferences with a reviewed snapshot at `homes/<user>/noctalia/config.toml` in the machine flake. Home Manager projects matching links. Keys and application data remain outside this workflow.

The snapshot includes wallpaper preferences. A GUI override can supersede the declared wallpaper; deploy dry-run reports the conflict. Colors are generated by [theme templates](desktop-session.md#themes) and are not captured.

To begin, track an empty snapshot:

```bash
mkdir -p homes/alice/noctalia && touch homes/alice/noctalia/config.toml
git add homes/alice/noctalia/config.toml
```

From `configuration.nix`, select it through the home module:

```nix
users.users.alice.home.workstation.noctalia.preferencesFile = ./homes/alice/noctalia/config.toml;
```

Without this declaration Noctalia manages its own settings. Validate a snapshot independently of live state:

```bash
noctalia config validate homes/alice/noctalia/config.toml
```

## Capture

```bash
nacre noctalia capture --dry-run
nacre noctalia capture
```

Capture exports effective preferences, filters owned sections, validates a staged candidate and replaces the snapshot atomically when changed. Validation warnings stop capture. It does not stage, commit or push; review labels and paths for personal information before committing.

`noctalia-config capture --check` writes nothing and names changed sections without their values. Exit 3 means drift. Doctor runs this comparison, including after an update.

## Deploy

```bash
nacre noctalia deploy --dry-run
nacre noctalia deploy
```

Deploy builds and activates the selected home, then verifies owned Noctalia sections without Arch convergence. Nacre supplies the machine checkout as `--repo` and forwards input overrides.

Conflicting GUI overrides stop deployment. To replace owned overrides deliberately, stop the shell first:

```bash
systemctl --user stop noctalia.service
nacre noctalia deploy --replace-overrides
systemctl --user start noctalia.service
```

Unowned sections remain unchanged. Replacement writes private recovery state before modifying overrides.

## Recovery

An interrupted replacement leaves receipts and backups under `~/.local/state/nix-config/noctalia-config/`. Keep them, stop Noctalia and run:

```bash
nacre noctalia deploy --recover
```

Recovery restores content only while current state matches the recorded transition; concurrent edits require manual resolution.
